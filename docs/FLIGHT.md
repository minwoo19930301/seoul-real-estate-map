# 서울 지도 비행 모드

상단 **비행기 모드**를 누르면 현재 위치에서 1인칭 비행을 시작한다. 기존 지도의 지형과 건물 모형을 그대로 사용한다. 별도 비행기 외형이나 예전 게임의 건물 장면을 추가하지 않는다.

## 이식 출처

원본은 같은 소유자의 [seoul-flight-game](https://github.com/minwoo19930301/seoul-flight-game/tree/792696011ee53921020ccbbf5f39105081da06bc), 기준 커밋은 `792696011ee53921020ccbbf5f39105081da06bc`이다.

- [`flight-model.mjs`](https://github.com/minwoo19930301/seoul-flight-game/blob/792696011ee53921020ccbbf5f39105081da06bc/flight-model.mjs): 피치·뱅크·방향타 반응, 지수 감쇠, 여러 입력의 독립적인 눌림 상태.
- [`seoul-flight.mjs`](https://github.com/minwoo19930301/seoul-flight-game/blob/792696011ee53921020ccbbf5f39105081da06bc/seoul-flight.mjs): `updateFlight`, `updateCamera`의 이동·자세, 74/116m/s 속도, 일시정지·포인터 잠금 흐름.
- [`terrain-lod.mjs`](https://github.com/minwoo19930301/seoul-flight-game/blob/792696011ee53921020ccbbf5f39105081da06bc/terrain-lod.mjs): 지형 위 18m 안전고도 정책.

현재 구현은 `src/flight-model.ts`의 독립적인 이동 계산, `src/flight-view.ts`의 MapLibre 카메라·입력 수명주기, `src/main.ts`의 모드·HUD 연결로 나뉜다. 원본도 별도 항공기 GLB가 없는 1인칭 카메라 방식이다. 원본 전체를 MIT로 재표기하지 않는다. 원본의 Three.js MIT 고지는 해당 라이브러리에 대한 것이며, 이식에 별도 vendor 파일을 복사하지 않았다.

## 조작

| 입력 | 동작 |
| --- | --- |
| W/S 또는 ↑/↓ | 상승·하강 자세 |
| A/D 또는 ←/→ | 좌우 뱅크와 선회 |
| Q/E | 좌우 방향타 |
| Shift | 가속, 목표 116m/s |
| Ctrl | 감속, 목표 40m/s |
| L | 수평 자세로 복귀 |
| Space/P | 일시정지·재개 |
| R | 자세·속도 복구, 지면 위 최소 150m로 상승 |
| Escape | 비행 종료 |
| 마우스 조종 버튼 | 지원하는 데스크톱에서 포인터를 잠근 뒤 마우스로 방향·피치 조작 |

포인터 잠금이 브라우저에 의해 해제되면 비행을 일시정지한다. 따라서 잠금 중 Escape가 브라우저에 소비된 경우 먼저 조종이 멈추며, 비행 종료 버튼으로 지도에 돌아갈 수 있다. 터치 화면에는 상승·하강·선회·가속·감속 버튼이 있다. 일반 비행 목표속도는 74m/s이며 즉시 전환하지 않고 완만하게 변한다. 원본의 Space 수평복귀는 여기서 L로 이동했고, Ctrl 감속과 현재 지도 위치 출발은 이식 과정에서 추가했다.

검색창·입력창에서 타이핑한 키는 비행 조작으로 취급하지 않는다. 창이 포커스를 잃거나 탭이 숨겨지면 입력을 모두 해제하고 정지한다. 탭에 돌아왔다고 자동으로 재개하지 않는다. 비행 종료 시 애니메이션 루프·포인터 잠금을 해제하고 이전 카메라, 기울기·회전·롤, 지도 조작 활성 상태와 2D/2.5D 모드·지형 배율을 복원한다.

## 좌표·고도와 한계

이동 거리는 지상 미터, 속도는 내부 m/s이며 HUD에는 km/h로 표시한다. 고도는 해수면 기준 미터, `지면 위`는 현재 지형 표면과의 차이다. 방위는 북쪽 0°, 동쪽 90°로 표시한다. 비행 중 지형 배율은 **1×**이며 지형 강조 슬라이더는 잠긴다.

출발 고도는 `max(0, 지형 고도) + 150m`이다. 매 이동의 최종 좌표에서 지형을 샘플링한 뒤 `max(0, 지형 고도) + 18m` 아래로 내려가지 않게 보정한다. 서울 비행 구역 경계를 넘으면 위치를 제한하고 안쪽으로 선회한다. 상한은 해발 1600m다. 한 프레임의 계산 시간은 최대 0.05초로 제한하여 장시간 멈췄다가 위치가 갑자기 도약하지 않도록 한다.

지형 소스가 아직 로딩 중이거나 샘플이 `null`/비유한 값이면 위치 이동을 보류한다. MapLibre의 숫자 0 반환만으로는 실제 해발 0m와 일부 무자료 대체값을 구별할 수 없으므로, 이 보정은 정밀 지형 충돌 판정이 아니다. 등고선에서 보간한 지형 자체에도 해상도·높이 한계가 있다.

**건물·교량·수목과의 충돌은 구현하지 않았다.** 건물을 통과할 수 있다. 실속·양력·항력·연료를 계산하는 항공 시뮬레이터가 아니라 원본의 아케이드 비행 조작을 지도에 연결한 기능이다.

## 카메라와 조회 제한

MapLibre의 `calculateCameraOptionsFromTo`로 실제 비행 위치와 약 300m 전방의 시선을 연결한다. 카메라 중심이 실제 비행 위치와 다르므로 데이터 조회는 별도로 보관한 비행 위치를 기준으로 한다.

- 카메라 갱신은 최대 약 50Hz, HUD 콜백은 10Hz, 위치 콜백은 4Hz로 제한한다.
- 조회 중심은 서울 기준 100m 격자에 맞추고, 주변 조회는 반경 800m인 사각 범위를 사용한다.
- 일반 지형·건물·도로·장소 자료 갱신은 위치 격자가 바뀌었을 때, 최소 1.2초 간격으로 예약한다.
- `CityModels`는 비행 카메라 이벤트와 카탈로그 선택을 1초 단위로 합친다. 기존 모형 메모리·활성 개수 제한은 유지한다.
- `flightView: true` 카메라 이벤트는 일반 `moveend` 데이터 갱신과 매 프레임 장소 핀 재생성을 유발하지 않는다.
- 비행 중 장식용 나무의 새 조회·생성을 중단한다. 지도 엔진의 일반 화면 타일 요청은 이 애플리케이션 조회 제한과 별개다.

## 검증

`node --test tests/flight-model.test.mjs`는 방향·미터 이동, 20/60/120Hz 선회, 속도 차이, 경계 후 지형 샘플링, 미확인 지형 보류, 긴 프레임 간격, 복수 입력, 소스 대기·일시정지·카메라 복원·콜백 제한을 검증한다. 실제 렌더링과 기존 모형의 보존 여부는 별도 브라우저 검증 대상이다.
