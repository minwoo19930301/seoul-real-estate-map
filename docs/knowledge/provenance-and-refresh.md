# 출처를 남기고 자료를 갱신하는 방법

## 내려받은 사실과 사용할 수 있는 범위를 구분한다

공개 페이지에서 다운로드가 가능해도 재배포·가공 조건이 자동으로 확인되는 것은 아닙니다. 자료마다 제공 기관, 원본 URL, 기준일, 취득일, 파일 해시, 인코딩, 행 수와 이용조건을 따로 기록합니다.

[공개 자료 조사 목록](../APARTMENT_SOURCES.md)의 조사 당시 기록에는 공공누리 4유형 2종과 재배포 조건을 확인하지 못한 자료가 포함됩니다. `OA-20281`, `OA-20286`은 기존 처리 규칙에 따라 원본 보존 대상으로 구분하고 가공·지도 표시에서 제외합니다. 이 문서는 새로운 이용 허락을 부여하지 않으며, 재사용자는 원문 조건과 최신 상태를 확인해야 합니다.

이 GitHub 저장소는 조사 방법과 코드, 공개 가능한 가공 자산을 제공합니다. 수집한 원본 파일·원본 DB·서버 인증 설정은 포함하지 않습니다. 코드가 원본 다운로드 경로를 제공하는 것과 그 원본을 저장소에서 재배포하는 것은 별도입니다.

## 원본, 연결 결과, 화면 표현을 따로 검증한다

| 단계 | 확인할 것 | 확인했다고 볼 수 없는 것 |
| --- | --- | --- |
| 다운로드 | 파일 SHA-256, 인코딩, 파일과 포털 건수의 차이 | 제공 기관 기록 자체의 정확성 |
| 적재 | 입력·출력 행 수, 서울 범위 필터, 원본 ID와 필드 보존 | 모든 서울 부동산의 수록 |
| 연결 | 공식 키 일치, 후보 수, 중복·누락·보류 사유 | 이름이 비슷한 대상의 동일성 |
| 지형·모형 | 원본 선·점 대조, 좌표계, 보간·추정 여부 | 모든 지점의 실측 높이 |
| 서비스 | API 응답, 검색·범위 조회, 표시 제한과 출처 | 장기간 무중단 운영 또는 데이터의 실시간성 |

포털의 행 수는 받은 날의 값입니다. 숫자가 바뀌면 무조건 수집 오류라고 판단하지 않고 제공일·갱신일·필터와 비교합니다. 반대로 API가 200을 반환했다는 이유만으로 실제 화면과 자료 연결까지 검증했다고 보고하지 않습니다.

## 갱신할 때 남길 기록

1. 새 원본을 기존 스냅샷과 구분해 보존하고 해시·기준일·이용조건을 확인합니다.
2. 파일 구조, 원본 건수, 식별자 중복과 누락을 검사합니다.
3. 기존과 같은 연결 규칙으로 결과를 만들고 새로 늘거나 빠진 연결의 이유를 확인합니다.
4. 서비스용 추출본과 원본 보관본을 구분합니다. 원본 DB를 화면 조회 편의에 맞춰 덮어쓰지 않습니다.
5. API·지도와 실제 배포 커밋을 확인한 뒤 변경 범위와 남은 한계를 기록합니다.

현재 운영은 조회용 Turso 서비스 DB와 원본 보관·분할 경로를 구분합니다. 코드 배포가 원본 DB를 자동 갱신하지 않으며, 데이터의 실시간 동기화도 구현된 것으로 취급하지 않습니다. 원격 DB를 교체할 때는 기존 스냅샷과 복구 경로를 먼저 확인합니다.
