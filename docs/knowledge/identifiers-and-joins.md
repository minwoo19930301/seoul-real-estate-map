# 같은 부동산을 가리키는지 확인하기

## 단지와 건물, 필지는 서로 다른 단위다

지도에서 아파트 이름 하나를 찾았다고 해서 그 단지의 모든 동과 거래 기록이 확정되는 것은 아닙니다. 한 단지에 여러 동과 필지가 있고, 한 필지에 여러 단지 후보가 존재할 수도 있습니다. 관리 단위와 건축물대장의 묶음도 항상 같지 않습니다.

| 대상 | 연결에 쓰는 식별자 | 주의할 점 |
| --- | --- | --- |
| 관리 단지 | K-apt 단지코드 | 관리 정보의 단위이며 모든 주택이나 개별 동의 키가 아님 |
| 한국부동산원 단지 | 단지고유번호 | K-apt 코드와 별도 체계이므로 값을 그대로 비교하지 않음 |
| 토지 필지 | PNU | 같은 필지가 같은 단지·동을 뜻하지 않음 |
| 도로명주소 건물 | 건물관리번호 | 여러 동이 공유할 수 있는 도로명주소관리번호와 구분 |
| 건축물대장 | 제공 시스템의 대장 PK | 시스템 전환과 자료 버전을 함께 보존 |
| 지도 도형 | Overture 건물 ID, 부분 도형 ID | 공식 단지코드·건물관리번호와 별도 체계 |

식별자는 선행 0을 잃지 않도록 문자열로 취급합니다. 건물 부분 도형은 한 건물의 높이·형태가 다른 부분이지, 별도의 아파트 동이나 세대가 아닙니다.

## 이 프로젝트의 연결 순서

1. 원본 코드가 정확히 일치하는 자료를 연결합니다. 서울시 공동주택 자료와 K-apt 기본정보처럼 공통 단지코드가 있는 경우입니다.
2. 코드가 없으면 공식 주소 요소로 만든 PNU를 비교합니다. 실거래·전월세·공시가격·대장·인허가는 이 경로로 단지에 연결합니다.
3. 주소 기반 자료는 도로명주소 건물DB 등을 통해 필지가 하나로 확정되는 경우에 연결합니다. 이름 유사도만으로 후보를 확정하지 않습니다.
4. 후보가 여럿이면 모두 보존하거나 연결을 보류합니다. 결과를 늘리기 위해 첫 번째 후보를 선택하지 않습니다.

K-apt 목록에서 사용하는 PNU 조합은 `법정동코드(10자리) + 대지구분(1자리) + 본번(4자리) + 부번(4자리)`입니다. 현재 목록의 조합은 대지 구분을 전제로 하므로 산 필지를 동일하게 추정해서는 안 됩니다. 대표 필지 하나만 제공되는 다필지 단지는 연결에서 빠질 수 있습니다.

## 연결 성공을 과대 해석하지 않기

같은 PNU로 연결된 거래는 해당 필지의 기록입니다. 그것만으로 지도에서 선택한 개별 동이나 특정 세대의 거래임을 보장하지 않습니다. 도형과 대장의 주소가 일치해도 여러 동·부속 건물·구관과 신관이 섞일 수 있습니다.

주소키가 한 자료 안에서 유일하다는 사실도 다른 자료와 일대일로 대응한다는 뜻은 아닙니다. CSV 내부의 중복 검사와 실제 도형 연결 검증을 따로 해야 합니다. 좌표가 가깝거나 이름이 같다는 조건만 충족했다면 확정 연결과 구분해 표시합니다.

연결 기록에는 사용한 키, 원본 식별자, 자료 버전, 후보 수와 보류 사유를 남깁니다. 단지 총 동수는 결과 검산에 쓸 수 있지만, 빠진 동의 도형을 임의로 만드는 근거로 쓰지 않습니다.
