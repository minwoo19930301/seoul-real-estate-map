# 사진·도면 대조에 따른 개별 모델 재작업

기존 주거·공공기관 생성기는 원천 외곽선에 반복 입면과 추정 색상을 입혔다. 파일별 해시나 색상이 달라도 실물에 맞춘 개별 모델이라는 뜻은 아니다. 기존 PR/소스 조사 결과는 [template-provenance.json](template-provenance.json)에 기록했다.

현재 저장소에는 개별 제작 GLB 72개가 있으며, 이전 버전 보존 파일도 포함한다. 유효한 주거동별 검증과 단지 완료 여부는 [전수 현황](apartments-400-summary.md), 파일별 출처·렌더·해시는 [개별 대조 기록](published-bespoke.json)을 기준으로 확인한다. 서울 전수 작업 완료를 뜻하지 않는다. 실제 Blender 4.5.11 LTS와 `mcp-for-blender`의 `execute_blender_code`를 사용했고, 작성자와 별도로 사진과 최종 렌더를 대조했다.

## 겹침과 실패 시 동작

원본 모델 파일을 덮어쓰지 않는다. 새 모델이 지형과 함께 실제로 그려진 뒤에만 지정한 원본 모델/건물 외곽선을 숨긴다. 한 복합 모델을 여러 동으로 교체할 때 화면 안의 새 동 하나가 실패하면 기존 복합 모델을 유지한다. 기존 랜드마크 우선순위는 보존한다. 백화점처럼 구획의 공통 층수가 엉뚱한 외곽선에 적용된 경우, 잘못된 모델을 정확히 지정해 대체한다.

## 현재 우선순위

2026-09-21 요청에 따라 **서울 400세대 이상 아파트의 모든 주거동**을 먼저 개별 제작한다. 큰 상가는 단순화한다. 랜드마크·문화재 등 기존 정밀 모델은 보존한다.

[공식 관리코드별 큐](apartments-400-queue.jsonl.gz), [동별 대응과 승인](apartments-400-coverage.json), [집계](apartments-400-summary.md)를 사용한다. 서울시·K-apt를 합친 1,417개 대상 관리코드 중 실제 고유 단지 수는 중복 관계 검토 전이므로 확정하지 않는다. 사진·도면·MCP·GLB·편집본 증거가 모두 연결되고 해당 주거동 전부를 검토한 경우만 완료로 센다.

메이플은 29동 중 11동, 원펜타스는 6동 중 2동을 검증했다. 이전에 대장과 충돌했던 메이플213은 교정본으로 대체했다. [다음 동 조사](maple-next-buildings.md)와 동별 출처 기록에서 남은 대응을 관리한다. [기존 높이 감사](apartments-400-existing-height-audit.json)와 [타워팰리스 높이 기준 검토](tower-palace-height-datum-review.md)도 참고한다.

2026-09-21 사용자 지시에 따라 **앞으로 자료 조사는 GPT 5.6 Luna 서브에이전트, low reasoning**에 맡긴다. 실제 개별 모델링은 Astra가 담당하고, 작성자와 별도의 최종 사진 대조를 거쳐 반영한다. 조사 메모만 작성된 동이나 원베일리의 미승인 모델에는 완료 크레딧을 주지 않는다.

첼리투스101이 과거 이촌왕궁 복합 모델 안에 묶였던 오류는 [원본 보존 분리](caelitus-generic-split.json)로 수정했다. 원본 GLB는 유지하고 동일 삼각형을101과 이웃6개로 나눠, 새101이 이웃을 숨기지 않게 한다.

## 검증

- Node 회귀 검사와 Python CI 검사를 실행한다. 실행 결과는 변경 배치의 검증 기록 및 CI에 남긴다.
- GLB의 유효 좌표·법선·지면 기준·앵커·SHA, 편집 원본 SHA, 실제 MCP 성공 기록 검사.
- 게시 중 메타데이터 교체 실패를 주입한 수동 검사에서 기존 파일과 메타데이터 복구 확인.
- 지도 브라우저 검사에서 기존 8개 현장·이웃·랜드마크·강제404·메이플29개 동과 신규 문화시설 3곳의 정상/실패 전환을 확인한다. 기존 결과는 [지도 화면](renders/map), `browser-check.json` 및 기존 landmark/reference 검사 기록으로 남긴다.
- 로컬 검증과 공개 배포는 별개다. 배포 완료 여부는 CI와 공개 release SHA/모델 해시로 확인한다.
