# 서울고속버스터미널 경부·영동선: 개별 모델 제작 근거

조사일: 2026-09-20. 이 문서는 **현존 경부·영동선 터미널**의 재제작을 위한 근거 기록이다. 센트럴시티 호남선·신세계·JW 메리어트와 구분한다. 운영사 사진·안내도는 직접 열어 확인했지만 사진 촬영일과 실측 입면도는 확보하지 못했다. 따라서 외관의 특징을 복원할 근거는 확보했으나, 2026년 현장 실측 또는 사진측량 모델이라고 주장할 수 없다.

## 현재 표시의 원인

- 원본 도형 ID: `c313b964-022c-4f5a-9599-d69d0155d010`, 이름 `서울고속버스터미널`, OSM `w309352819@19`. [OSM 도형](https://www.openstreetmap.org/way/309352819).
- `data/buildings.sqlite`는 ㄱ자 전체를 하나의 Polygon으로 보유한다. `height_m=51`, `num_floors=9`, `has_parts=0`, `extrude=1`, `parent_id=null`이다. 높이가 다른 본관과 긴 부속 익부의 분리가 없다.
- `public/models/footprint-matches.json`에는 이 ID를 대체하는 GLB가 없다. legacy manifest와 reference manifest에도 경부·영동선의 독립 정밀 자산은 없다. 따라서 대상은 기존 GLB를 정교하게 만드는 작업이 아니라 **원본 단순 extrusion을 개별 제작물로 대체하는 작업**이다.
- `reference-flight-central-city` / `reference-flight/central-city.glb`는 다른 시설이다. 원본 Flight `landmarks/central-city.mjs`는 JW 메리어트·신세계와 호남선 터미널을 제작한다. 경부선 모델로 재사용하면 대상부터 틀린다. 현 자산 크기는 약 117 × 144.2 × 117m이며 높이는 호텔에 해당한다. 소유 ID `3eae786b-e34b-4ab7-ac75-04de84238fd2`와 `bf07fa32-2bb1-45f4-95d9-eb4d863f0c34`는 이번 교체 대상이 아니다.

## 모델에서 반드시 달라져야 하는 형태

1. **본관과 낮은 익부의 높이를 분리한다.** ㄱ자 외곽 전체를 51m 높이로 세우지 않는다. 서쪽 본관은 긴 높은 몸체이고 신반포로 방향의 긴 팔은 낮은 부속상가·승하차 공간이다. 운영사의 층수 구분과 전경 사진 모두 이 차이를 지지한다.
2. **본관의 끝단과 동쪽 입면을 입체로 만든다.** 단순 직육면체에 창문만 붙이는 방식으로는 식별되지 않는다. 전경에서 보이는 쐐기형/후퇴형 단면, 두꺼운 수평 바닥선, 층별 그림자 깊이, 하부의 큰 개방 구간이 주요 특징이다. 경사 각도와 각 층의 후퇴량은 사진 기반 추정으로 기록한다.
3. **낮은 익부는 상자 벽으로 막지 않는다.** 승차홈 쪽 기둥·개방부·지붕/데크를 구분하고 버스 마당은 빈 공간으로 남긴다. 데크 아래 검은 공간과 지붕 상부 주차의 차이가 중요한 원경 단서다.
4. **밝은 회백색 구조체, 어두운 연속 창호, 파란 상부 간판 면을 분리한다.** 사진의 따뜻한 야간 빛을 건물 고유의 노란색으로 오인하지 않는다. 실제 사진에서 확인한 계열로 재질을 수동 설정하고 seed 팔레트를 사용하지 않는다. 보이지 않는 후면을 같은 정밀도로 확인했다고 주장하지 않는다.
5. **옥상은 평평한 한 장의 판으로 끝내지 않는다.** 10층의 외부 보행 띠, 경사진 간판 벽, 후퇴한 상부 구조, 난간을 별도 제작한다. 촬영 시점이 불명확한 광고 내용은 복제하지 않는다.

## 좌표와 치수의 출처

지리 도형은 현재 저장된 OSM 기반 원본을 사용한다. 아래 계산 길이는 위도 37.5054에서 경도·위도를 국소 미터로 환산한 대략값이며 건축 실측 치수가 아니다.

- 전체 source centroid: **lon 127.00620195, lat 37.50541550**. ㄱ자 전체의 중심이지 높은 본관의 중심은 아니다.
- 전체 bounds: `[127.0049482, 37.5042468, 127.0084228, 37.5065905]`.
- 북쪽 긴 외곽선: `[127.0049482, 37.5055730]` → `[127.0083005, 37.5065905]`, 약 **317.0m**, 동쪽 기준 반시계 약 **20.9°**.
- 본관 서쪽 외곽선: `[127.0049482, 37.5055730]` → `[127.0055703, 37.5042468]`, 약 **157.5m**, 동쪽 기준 약 **−69.6°**.
- 본관 안마당 쪽 선: `[127.0063706, 37.5045105]` → `[127.0058570, 37.5055809]`, 약 **127.5m**. 남쪽 다각형 끝단과 북쪽 접합부 때문에 양쪽 길이가 다르다.
- 긴 익부 동쪽 끝 폭: `[127.0084228, 37.5063347]` → `[127.0083005, 37.5065905]`, 약 **30.5m**.
- **51m는 저장된 OSM 높이 값**이다. 운영사 실측값을 찾지 못했다. 모델 초기 envelope로 사용하더라도 증거 수준을 `source-reported, not independently measured`로 남긴다. DB 9층과 운영사 10층 표기는 불일치하므로 DB 층수를 그대로 반복하지 않는다. 옥상층 산입 차이 여부는 확인하지 못했다.
- 낮은 익부의 정확한 처마 높이, 개별 층고, 기둥 간격, 경사각, 간판 크기는 아직 미확인이다. 별도 추정 항목으로 남겨야 한다.

인접 원본은 자동으로 한 단지 소유권에 넣지 않는다. 별도 신관 후보 `889960cf-960d-4627-8005-86886ca7be4e`(centroid 127.00631466, 37.50388794, OSM w414891732), 마당 주차 구조 `87c691e9-3433-4f91-9bc0-f4b05be91a7c`(127.00712600, 37.50540968, OSM w356129682, source class parking), 남쪽 마당 건물 `26f1f742-5588-4727-b7a8-83833a6244fd`(127.00708928, 37.50471265, OSM w356129683)은 별개 도형이다. 이 중 실제 모델로 제작하고 지리적으로 대응시킨 부분만 교체 대상으로 삼는다.

## Blender 제작안과 검수

모델은 이 터미널만을 위한 별도 컬렉션으로 작성한다. 지역 전체 공장식 생성기 또는 기존 아파트 facade 함수는 사용하지 않는다.

1. 원본 외곽을 Blender 미터 좌표계로 가져온 뒤 본관/접합부/낮은 익부를 나눈다. 원본 방향을 유지하며, 높은 본관의 중심을 임의로 전체 bbox 중앙에 놓지 않는다.
2. 본관의 실제 남쪽 끝단을 기준으로 층별 단면을 수동 작성한다. 서쪽 높은 벽, 동쪽 후퇴/경사면, 남단의 모서리 형태를 먼저 맞춘다. 옆면·대각선 카메라에서 운영사 전경과 실루엣이 맞기 전에는 창문 수를 늘리지 않는다.
3. 각 층 슬래브를 별도 높이·깊이로 배치하고 입면 기둥/리브와 깊이 있는 창호를 작성한다. 반복은 이 건물에서 확인한 연속 부재에만 사용한다.
4. 낮은 부속상가와 승차장 캐노피/데크를 작성한다. 사진과 안내도의 기둥·승차홈 방향을 맞추고 중앙 마당을 비워 둔다. 확인되지 않은 주차 구조와 신관은 이번 주 건물의 일부인 것처럼 덮지 않는다.
5. 옥상 경사벽·외부 통로·간판·난간을 추가한다. 실제 글꼴/크기가 확인되지 않은 글자는 과장하지 않는다. 사진은 관찰 자료로만 사용하며 이미지 텍스처 재배포는 하지 않는다.
6. Blender MCP로 정면, 남쪽 끝단, 버스 마당 쪽, 위쪽 네 시점을 저장해 원본 사진/안내도와 대조한다. 낮은 익부가 높은 본관과 분리되는지, 삼각형 끝단이 읽히는지, 마당이 막히지 않는지가 첫 합격 조건이다.
7. GLB는 지리 기준점과 지면 오프셋을 따로 기록한다. footprint ownership은 제작된 부분에 한정하고, 기존 호남선 GLB와 주변 원본을 보존한다. 실제 지도에서 지형 접지, 기존 단순 도형 잔존·과도한 숨김, 높이비를 검수한 뒤 게시한다.

## 제작 결과와 남은 한계

조사 후 전용 Blender 4.5.11 인스턴스(port 9876)를 실제 MCP `get_scene_info`로 확인하고 `execute_blender_code`로 개별 장면을 작성했다. 재현 소스는 `scripts/bespoke/express_terminal.py`, 4개 시점 렌더는 `scripts/bespoke/express_terminal_render.py`, GLB 바이트 검사는 `scripts/bespoke/express_terminal_validate.py`다. 기존 모델 생성기의 facade 코드는 호출하지 않는다.

편집 가능한 `.blend`, GLB, `bundle.json`, `report.json`, `geometry-validation.json`, 실제 MCP 실행 기록과 렌더는 ignored staging인 `data/model-source/bespoke/express-terminal/`에 저장한다. 장면은 본관 단면, 후퇴 입면, 옥상 간판/테라스, 낮은 익부, 승차홈, 끝벽/계단의 6개 건축 컬렉션으로 구분한다. 사진은 장면/GLB에 포함하지 않았다.

첫 렌더를 운영사 전경과 비교해 높고 낮은 두 팔과 본관 끝단의 경사 실루엣을 확인했다. 간판 글자와 1층 기둥이 몸체 면에 가려진 문제는 렌더 확인 후 수정했다. 두 번째 비교에서는 간판 폭과 옥상 실루엣을 보완했다. 한글 간판은 본관 길이의 약 절반에 해당하는 폭으로 맞추고, 중앙의 따뜻한 색 서비스 블록·세로 슬릿과 양 끝 직사각형 광고판의 프레임/빈 패널을 분리했다. 광고 내용은 복제하지 않았다. 51m 전체 높이 안에서 서비스 블록을 드러내기 위해 옥상 보행면은 약43.2m로 해석했으며 이 값은 실측이 아니다. 남북 끝벽의 큰 수직/경사 테두리는 AKS 전경에서 읽히는 구조적 깊이만 보강했다.

현 모델은 **사진과 안내도를 근거로 개별 제작한 해석 모델**이며 정확한 층별 단면, 캐노피 위치/반경, 뒷면의 모든 창 배치, 최신 광고·점포 입면을 전수 실측한 복원물이 아니다. 운영사 사진의 저해상도와 촬영일 미표시 한계는 그대로 남는다. 공장식 상자 모델을 대체할 주요 특징은 재현했지만 사진측량 수준의 정확도를 보증하지 않는다.

게시 manifest·runtime과 공용 GLB는 이 작업에서 변경하지 않는다. 통합 시 원본 ㄱ자 source ID 하나만 소유하며 별도 주차장/신관/호남선 시설은 보존한다.
