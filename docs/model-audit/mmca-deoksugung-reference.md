# 국립현대미술관 덕수궁관 · 석조전 서관

## 개별 형상

남북으로 긴 두 전시실 날개, 중앙 돌출부, 폭이 좁은 양 끝 계단실을 별도 질량으로 만든다. 전면 큰 창에는 깊이 있는 개구부, 어두운 유리·금속 창틀, 돌출 석재 창대와 상인방을 넣고 위쪽의 넓은 벽을 남긴다. 자동 사무실처럼 위층 창을 반복하지 않는다.

현관 기둥 사이를 막는 상자를 두지 않는다. 여섯 기둥은 각각 테이퍼와 약한 엔타시스가 있는 매끈한 몸체, 여러 단의 둥근 주초, 잎·말림 장식 주두와 사각 상판으로 구성된다. 기둥 뒤의 중앙 문과 두 큰 창, 위층 작은 세 창은 날개와 별도 배치다. 평평한 석재 처마·프리즈·작은 받침·난간층을 분리했고, 동관의 삼각 페디먼트는 넣지 않았다.

23개의 독립 계단은 3.40m 입구 높이에 맞춰 분배했다. 단 높이 약 0.148m와 전체 길이 6.3m는 저자가 선택한 비례값이며, 안내문이 계단 치수를 제공했다는 뜻은 아니다. 넓은 층계와 양쪽 무거운 석재 난간/기단을 만들되 분수까지 이어지는 정원 계단·보행로는 제외했다.

2018 사진에서 확인한 중앙 지붕은 밝은 **불투명 박공**으로 별도 작성하고 북쪽 끝면에 작은 어두운 사각 개구부를 넣었다. 나머지 네 개의 낮은 날개 지붕 채광 덮개는 source polygon의 내부 ring 위치를 참고한 **미확정 해석**이다. 방문자 평면에 점유된 전시실이 있으므로 그 ring을 지상까지 뚫린 중정으로 처리하지 않았다. 정확한 채광 구조·재료·경사도를 검증했다는 주장은 하지 않는다.

후면에 정면의 장식 현관을 복제하지 않는다. 후면과 끝단의 일부 서비스 개구부는 보수적인 추정이며 창 개수·입면이 실제와 정확히 일치한다고 주장하지 않는다. 주요 형태의 공식 근거는 정면과 높은 시점의 사진이다.

## 실제 제작·검토와 재구성

독립 검토에서 양 끝 처마 접합부의 검은 띠를 발견했다. 이는 실제 구조 틈이 아니라 서로 확장된 처마 상면의 중첩이었다. 공유 경계의 중복 확장을 없애고 전체 지붕이 잘리지 않도록 평면 카메라를 고쳤다. 중앙 지붕도 첫 유리 덮개 해석을 버리고 워크북의 불투명 박공·작은 개구부로 수정했다. 창·기둥·계단을 임의 난수나 공통 건물 분류로 배정하지 않았다.

편집 가능한 `mmca-deoksugung.blend`에 형상·재질 9개 구성 그룹과 별도 `REVIEW_ONLY_NOT_EXPORTED` 카메라/조명/바닥이 있다. Blender 축은 동 X·북 Y·위 Z, GLB는 동 X·위 Y·남 Z다. 모델 좌표를 개별 지리 앵커에 이미 맞췄으며 GLB 노드에는 추가 이동·회전·축척이 없다. 원본 `.blend` 자체가 재편집 가능한 산출물이며, 스크립트 전체 재실행을 위해선 입력 JSON과 작동하는 전용 Blender MCP가 필요하다.

```sh
python3 scripts/bespoke/mmca_deoksugung_prepare.py
/tmp/seoul-blender-mcp-env/bin/python scripts/bespoke/blender_mcp_client.py execute \
  --port 9877 --script scripts/bespoke/mmca_deoksugung_blender.py \
  --record data/model-source/bespoke/mmca-deoksugung/mcp-build-v4.json
python3 scripts/bespoke/mmca_deoksugung_finalize.py --proof mcp-build-v4.json
```

준비 단계는 보존한 `source-footprint.json`을 읽는다. 지오메트리 빌더는 stage에 입력이 없으면 `modeling/bespoke/mmca-deoksugung`의 커밋된 입력을 읽도록 구성했다. 준비 스크립트를 재실행하면 authored 입력을 다시 쓰므로 변경된 수동 결정을 유지하려면 준비 코드와 입력을 함께 관리해야 한다. 사진·PDF를 자동 다운로드하거나 서버를 자동 실행하는 명령은 아니다.

렌더는 정면 전체, 현관 근접, 공식 워크북 대응 높은 시점, 전체 지붕 평면, 후면 한계 확인의 다섯 개다. 실제 MCP 호출 기록, GLB의 finite 좌표·법선·minY=0·이미지 미포함 검사와 SHA는 stage의 `geometry-validation.json`/`bundle.json`에 보존한다. 출판과 지도상 중첩·공개 배포 검증은 별도 통합 과정이며 이 문서만으로 배포 완료를 뜻하지 않는다.
