# 메세나폴리스 — 주거 3동과 간략한 주거측 상가

개별 재제작 범위는 **A12174601, 617세대, 주거101·102·103동**입니다. 별도 세아타워 업무동, 문화집회동 및 이웃 건물은 포함하지 않습니다. 서울 전체 아파트나 메세나 복합시설 전체를 정밀 완성했다는 의미가 아닙니다.

## 직접 대조한 근거

- [AURUM 메세나폴리스](https://www.aurum.re.kr/Bits/BuildingDoc.aspx?num=5119&page=1): 한국건축문화대상2014 설계사 자료. `source-ledger.json`의 원문 이미지URL와SHA로 추적합니다. 완공사진 `aurum-07.jpg`·`08`·`09`를 지상 입면, `00`·`01`을 중앙부로 확인했습니다. 실제사진00–24와 설계그림25–27을 구분했고, 후자는 외관 제작 근거로 쓰지 않았습니다. 사진 촬영일은 별도 확인하지 못했습니다.
- 같은 공식 자료의 **28 옥탑지붕,29 지상22–26층,45 횡단면,47–49 입면,50 배치도**를 실제 이미지로 열어 확인했습니다. 반복된 세 동의 삼각 평면과 꺾이는 외곽, 날개벽, 3개의 비대칭 삼각 유리 스크린, 작은 중앙 육각 헬리패드가 확인됩니다. 지상층은 곡선을 임의로 만든 것이 아니라 도면의 각진 평면을 추적했습니다.
- [설계사 제공 건축문화2012.11](https://www.ancbook.com/contents/anc/2012/11/03.htm): 101·102동39층,103동29층, 별도업무32층. [2012.12 정정](https://www.ancbook.com/contents/anc/2012/12/18.htm)은 EAWES의 전체·타워 설계와 JERDE의 저층상업 설계를 구분합니다.
- [JERDE 실제 상업부 사진](https://www.jerde.com/projects/7849/mecenatpolis): 굽은 석재 테라스, 계곡형 열린 동선, 유리 연결다리. 상업부는 사용자 요청 범위에 따라 간략화했습니다.
- [서울시 공동주택 OA-15818](https://data.seoul.go.kr/dataList/OA-15818/S/1/datasetView.do): 관리코드·617세대·3동. 주거 세대수에 업무동을 합산하지 않았습니다.
- [공개 건축물대장 OA-22424](https://data.seoul.go.kr/dataList/OA-22424/S/1/datasetView.do): 정확 지번 서교동490/양화로45에서 공동주택 행 `10151100207031`,39F·137.4m·617세대. 별도 오피스 행은32F·164m, 몰12.6m, 문화집회동17.4m. 원본행과 source_hash는 `register-rows.json`에 보존합니다.

## 좌표·높이와 확인 한계

동 번호별 named OSM footprint 중심에 각 GLB를 독립 배치합니다. 29층 북측 동은 도면과 명확히 대응합니다. 공식 배치도에101/102 숫자가 직접 쓰인 것은 아니므로, 나머지 번호는 named source와 설계사의 번호별 층수·도로방향을 합친 근거입니다. 지적측량으로 표현하지 않습니다.

전형층 도면의50m 그래픽 축척으로 직접 추적한 약48.0×42.4m/1287㎡ 외곽은 기존 OSM2100㎡보다 작습니다. 모델을 거친 OSM 크기로 부풀리지 않았으며 비교도/면적은 `source-profile-comparison.*`에 남겼습니다. 도면회전각은 source 긴 입면과 도면 북향을 대조한 약 -74도입니다. 모서리 오차·도면 정합은 측량 수준이 아닙니다.

**137.4m는 동별 최상단 실측이 아닌 공동 아파트 대장 한 행**입니다. 본 모델은 이를101/102의 스크린까지 포함한 보수적 전체 envelope로 해석했습니다. 미세 프레임 두께 포함137.466m입니다. 103동은10개 전형층 높이 차이를 빼 약106.799m이며 독립 실측값이 아닙니다. 대장 높이 기준점과 장식 옥탑 포함 여부가 불명확하므로 실제 상단 높이가 확정됐다고 쓰지 않습니다. 업무164m를 아파트에 복사하지 않았습니다.

헬리패드는 실제 도면처럼 **6개 변**입니다. 중앙 설비실은 더 작은 육각 범위에 두고, 루버·검은 경사지지부·얇은 상부판을 사진에 맞춰 분리했습니다. 후면 일부 창호, 장식부 치수, 루버 세부, 상가 점포·층별 상세와 조경은 도면/사진 기반의 근사입니다. 소유권·측량용 모델이 아닙니다.

## 기존 자산과의 관계

- 교체 compound: `apt-a12174601`. 기존 `footprint-matches.json`는 정확히 주거3동 UUID만 가집니다.
-101: `0b1a005f-1a8a-4512-8d8d-3b57fbb5595c`
-102: `6ffa9ebe-1efb-4f4e-a708-5d963a81a2bf`
-103: `f2ccf188-0531-4186-b461-80133f83d502`
- 보존 업무동: `b028f776-57de-460a-ad6f-4f0919b2d0e7`. 어떤 새 asset도 이 UUID를 소유하지 않습니다.
- 상업부에는 근거 없는 추가 footprint ID를 부여하지 않았습니다. 원래 도면의 주거측 공간을 간략화하고, 업무·문화동이나 외곽 도로를 포함하지 않았습니다.
- 인근 lazy survey타일도 확인했습니다. 주거 compound 내부를 덮는 추가 survey 모델은 없었고, 인접 `survey-upis-32688666`은 별개 빌라이므로 보존합니다.

네 자산 모두 같은 옛 compound를 supersedes하므로 부모 통합 시 전체 peer fallback 정책을 적용할 수 있습니다. 개별 주거GLB는 서로 다른좌표/지면앵커를 갖습니다.

## 재구성

1. 저장된 `mecenatpolis.blend`를 Blender4.5에서 바로 열어 편집할 수 있습니다. `REVIEW_ONLY_NOT_EXPORTED`에는 카메라·바닥·조명이 있으며 GLB에는 포함되지 않습니다.
2. 같은 폴더의 `build.py`와 `recipe.json`만으로 Blender Python에서 재생성합니다. `build.py`는 자기 파일위치만 사용하며 외부DB나 네트워크를 호출하지 않습니다. 전용 세션에 MCP `execute --script /path/build.py --port9877` 또는 Blender `--background --python /path/build.py`로 실행할 수 있습니다. **생성 시 해당 Blender 장면을 새로 구성하므로 저장한 사용자 장면에서는 실행하지 마세요.**
3. trace 입력 재생성은 선택적입니다. `prepare.py`는 함께 보존한 `residential-source-footprints.json`과 numpy/shapely를 사용합니다. 원본사진이 없어도 이미 authored pixeltrace와 recipe로 동일 형상을 재생성할 수 있습니다.
4. `validate.py`는 표준 Python으로 GLB 유한좌표·단위법선·ground0·transform bake·외부이미지없음·독립source소유를 확인합니다. `render-v2.py`는 저장 장면에서 비교6뷰를 만듭니다.

원본사진·설계도는 무허가 재배포하지 않습니다. GLB와.blend에 사진·도면 텍스처를 넣지 않았고, 별도 공개 recipe에는 작성한 좌표와 공개출처URL만 보존합니다.
