# 메이플자이 203동 개별 제작 검토 후보

공식 배치도·두 방향의 GS 항공사진·GS 준공 파노라마와 W41–44 근접사진을 직접 열어 비교했습니다. **203동 하나만 교체하며, 이웃204/202·별도 공사현장·공용 정원·선큰·방음벽은 포함하지 않습니다.** 214 및 215v2 등 이전 동결 모델을 수정하지 않았습니다.

## 번호·방향 식별

- [공식 번호 배치도 P](https://www.xi.co.kr/Files/cmsPage/20240205_132346_189001.jpg)의 남단 고속도로 모서리, 6라인 L형이203입니다. 메이플은101–114/201–215이고216은 없습니다.
- [GS 2월 B](https://www.xi.co.kr/Files/aptProcRateImg/20250403_170447_204001.JPG)의 가장 앞·고속도로 옆 낮은 L이203, 그 뒤 높은 동은204입니다. B에서 왼쪽 긴 면은 e5 SW, 오른쪽은 e4 SE입니다.
- [GS 3월 A](https://www.xi.co.kr/Files/aptProcRateImg/20250403_170535_099001.JPG)는 동쪽 반대 방향에서 e4 SE와 e3 NE 끝면을 봅니다. 내부 코어 일부도 보입니다.
- [방문사진 W41–44](https://first.useful2know.com/m/entry/%EB%A9%94%EC%9D%B4%ED%94%8C-%EC%9E%90%EC%9D%B4-%EC%9E%84%EC%9E%A5%EA%B8%B0-202503)는203 캡션·동선과 L 코어/주변건물/창군을 교차 대조했습니다. W41은 북쪽에서 e3→e2/e1 안쪽 코어를, W43은 동쪽에서 e4와e3 코너를 봅니다. 숫자203을 사진 안에서 직접 읽은 것은 아닙니다.
- `orientation.py`를 실제 MCP에서 실행하여 방위별 색 블록을 원본과 비교했습니다. 초기 NW/SW 근접사진 가설은 앞뒤 순서가 맞지 않아 버렸고, 최종 `W41_North_block`/`W43_East_block`을 채택했습니다. 오래된 가설 이미지는 연구 기록일 뿐 모델 근거가 아닙니다.

## 높이·면적의 한계

[공식 대장](https://data.seoul.go.kr/dataList/OA-22424/S/1/datasetView.do)의 정확한 잠원동167·203동 ID `1000000000000007633209`는 **19층,62.45m,107세대,건축면적782.481㎡**입니다. 원본 행과 SHA를 `register-row.json`에 보존했습니다. 종전29층/94.56m 추정은 사용하지 않습니다.

B의 SE 두 흰 창군에서 각각 주거창18행을 직접 셌습니다. 기단4.9m+18행×2.95m=58m 본체, 열린 핀60.55m, 설비실 최대62.35m로 나누었습니다. **공식62.45m 안에 배분한 envelope 추정이며 실측 층고나 옥탑 datum이 아닙니다.** SE의 겉보기 옥상 단차를 층수 손실로 해석할 근거는 없어 공통 본체 roof를 잠정 적용합니다. 수동4점 투시 보정 이미지는 행수 비교용 진단일 뿐 측량 자료가 아닙니다.

원본 anchor `127.01480752559553,37.51032812216982`와6점 trace를 정확히 유지했습니다. **삽도 trace1140.979㎡와 법정 건축면적782.481㎡가 크게 다르고, 배치도 축척/도로폭 및 면적 산입 경계 차이는 미확인입니다.** 임의 축소하지 않았으나 원본 trace 유지가 외곽 치수 정확성을 보장하지 않습니다.

창/패널 폭·후퇴·색·기단 개구부·핀/설비실/PV 치수는 원근 사진 추정입니다. 원본사진과 다른 단순화 및 숨은면 한계를 남기며, 모든 면이 실제와 일치한다고 주장하지 않습니다.

## 검증·재현

`build.py`는 옆의 `authored-input.json`을 읽어 실제 Blender MCP에서 단독으로 재생성합니다. 수학적 메쉬·법선·좌표 처리만 공통이며,203의 면별 창군·재료·배치·옥탑값은 새로 작성했습니다. `prepare.py`는 ignored 조사 원본을 참조하므로 최종 재현 recipe에 넣지 않습니다.

`validate.py`는 닫힌 양의 체적 메쉬·유한좌표·바닥0·보수적 높이·주요8개 창/기단 개구부의 첫 교차가 유리인지 검사합니다. `render_a.py`/`render_b.py`는 실제 MCP에서4뷰씩 렌더합니다. `package.py`는 GLB 좌표/법선/이미지 없음과 이전 모델의 동결 불변을 검사합니다. 이 검사는 사진 충실도 승인과 별개입니다. 원본사진은 ignored references에만 남기고 GLB에 삽입하지 않습니다.
