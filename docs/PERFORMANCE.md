# 로컬 지도 성능 — 2026-09-09

코드 전송량과 지도 이동 중 작업을 별도로 줄였습니다. 원본 높이·좌표·단지 세대수를 수정하거나 미등록 건물을 임의 높이로 채우는 방식은 사용하지 않습니다.

- `npm run build`에서 JS/CSS를 minify하고 JS/CSS/JSON/GLB의 gzip 파일을 미리 생성합니다. `npm start`는 이 운영 빌드를 4173에서 제공합니다. 개발용 Vite는 `npm run dev`로 별도 실행합니다.
- HTTP API는 1KB 이상 JSON에 gzip을 협상하며, q=0/identity를 존중합니다. 정적 압축 파일과 평문 모두 Vary를 보냅니다. 압축 해제 후 바이트가 원문과 일치하는 HTTP 테스트를 통과했습니다.
- Three.js 코드를 별도 chunk로 나누고 모델 GLB는 zoom13 이상에서 화면 근처만 한 번 로드합니다. 화면 밖에서는 draw하지 않습니다. 4종 총 원본 1,474,460 bytes를 매 화면 이동마다 다시 받지 않습니다.
- 지도 pixel ratio 기본 상한은 1.25입니다. DPR2 장치에서 이전 전체 해상도의 39.1% 픽셀만 그립니다. 이는 픽셀 개수 계산이며 FPS 개선율이 아닙니다. '화면 선명도'에서 1/1.25/2 상한을 바꿀 수 있습니다.
- 나무는 최대240개, 줄기·수관 두 InstancedMesh에 묶어 버퍼를 재사용합니다. 숲 내부·구멍·건물·도로 회피 계산은 별도 Web Worker에서 실행합니다. 원본 GeoJSON을 일반 객체로 변환하여 worker에 넘깁니다.
- 나무 제외 영역을 약200m 단위 중심 격자로 고정하고, 제외 도형 캐시는3영역, 나무 결과 캐시는6개로 제한합니다. 동일 영역의 진행 중 요청도 공유합니다. 타일 내용 갱신은 결과 cache key에 반영합니다.
- 건물·도로는 같은 범위의 직전 응답을 재사용합니다. 표시 토글만 바뀌면 불필요한 GeoJSON 재전송·setData를 생략합니다. 등고선도 동일 요청을 중복 실행하지 않습니다.
- 건물·도로의 렌더용 GeoJSON에서 스타일에 사용하지 않는 속성을 제거했습니다. 원본 geometry와 전체 속성은 컨트롤러에 유지하고 건물 클릭 시 원본 ID로 상세 정보를 복구합니다. 기존 전체 응답이 현재 화면을 완전히 포함하고 `truncated=false`일 때만 더 좁은 조회에도 재사용합니다. 캐시는 60초 유효하며, 불완전 응답으로 필요한 새 데이터를 가리지 않습니다.
- 최대 줌 24·기울기 85°의 근접 보기를 허용하되, 줌 19 이상·기울기 75° 이상에서는 상세 자료를 중심 ±300m의 **전체 600m 정사각형**에서 조회합니다. 지면의 화면 범위 밖에 있어도 가까운 고층 건물은 포함합니다. 건물·도로·등고선·장소 핀에 공통 적용하며, 기존 일반 화면의 넓은 건물·도로 캐시를 근접 모드에서 재사용하지 않습니다. 등고선 API에 보내는 줌은 최대 22로 제한합니다. 원본 geometry를 자르거나 단순화하는 변경은 아닙니다.
- 로컬 차도는 한 레이어의 연한 회색 중심선으로 표시하며 최대12px로 제한합니다. 보행로는 최대3px, 횡단선·계단은 최대3.5px, 대시 길이는 최대6px입니다. 선폭을 추정 미터 폭에 맞춰 확대하지 않으며 줌18.5→19 사이의 급격한 선폭 변화도 제거했습니다. 원본 좌표는 그대로입니다. 핀의 중복 조회·동일 상태 DOM 재생성을 생략하고, 마우스 좌표 텍스트 갱신은 최대 초당10회로 제한합니다.
- 줌19 이상·기울기75° 이상에서는 등고선·표고점과 라벨, 선택 연결선, 보간 음영, 건물 외곽선을 숨깁니다. 로컬 도로가 준비되면 온라인 배경 도로·도로 이름도 숨겨 중복된 선이 근접 화면을 덮지 않게 합니다. 일반 화면으로 돌아갈 때 원래 표시 설정을 적용하며, 이 정책으로 원본 자료를 삭제하지 않습니다.
- 자동 사람·차량 이동과 땀 효과를 제거했습니다. **사람 1인칭**에 진입한 동안에만 선택적으로 고정 크기 비교 모형을 표시합니다. 일반 지도는 최대 줌에서도 이 기능의 경로를 요청하지 않습니다. 카메라 진입 때 받은 경로를 재사용하며 정적 모형 컨트롤러에는 fetch·타이머·RAF·triggerRepaint 루프가 없습니다. 지도 렌더에 맞춰 필요한 화면만 다시 그립니다. [현재 동작](MOBILITY.md).
- 정적 모형은 최대 사람 1개·승용차 1개입니다. 미터 치수와 최초 세계 좌표를 유지하고 수동 카메라 조작 때만 화면 투영이 달라집니다. 발·바닥은 map.project, 몸체는 현재 지형과 공개 투영 행렬로 표시합니다. 지형 역투영과 일반 건물의 보수적 가림 판정을 사용하며 GLB 깊이 가림은 지원하지 않습니다. 사용할 수 있는 원본 길이나 보이는 자리가 없으면 해당 모형을 생략합니다.
- 사람 1인칭 모드는 추정 지면 위 약1.7m 카메라를 설정하며 지형1배를 사용합니다. 외부 카메라 조작의 `movestart`에서는 원본 마우스 이벤트 유무와 관계없이 길 고정 추적만 해제하고 현재 카메라·지형·지면 고정 정책을 유지합니다. 명시적인 **지도 시점**에서 저장한 카메라와 이전 모드·배율을 복원합니다. 실제 눈높이 줌은 화면 크기에 따라 달라집니다.
- 지형 갱신 후 눈높이 보정은 `setCenterElevation`으로 수직 높이 차이만 적용합니다. 매 `idle`마다 전체 카메라 위치를 다시 설정하던 경로를 제거해, 사용자나 API가 지정한 줌·중심점에 이전 고정값을 재적용하지 않습니다.
- 사람 1인칭 예시는 높이 기록이 있는 주변 건물을 함께 볼 수 있는 행당동입니다. 근접 화면의 일반 건물 입체는 불투명하게 표시하고, 정적 사람 모형은 1.7m 치수를 유지합니다. 이는 표현 조정이며 FPS 개선율 측정값이 아닙니다.
- Three.js에 상시 requestAnimationFrame/triggerRepaint 루프가 없습니다. 데이터와 모형·지도 라벨 전환이 끝난 뒤에는 재렌더링을 멈춥니다. 초기 map.loaded() 직후에도 예약된 나무 계산과 라벨 fade가 남을 수 있어, 실제 정지 구간을 따로 측정합니다.

## 과거 애니메이션 후보 탐색 측정 — 현재 기능에서 제거됨

이전 자동 이동 구현에서 `node scripts/measure-street-view.mjs`로 수집한 행당동 Chrome 1440×960 표본입니다. 아래 값은 당시 mobility 개발 hook을 사용한 기록입니다. 현재 같은 이름의 스크립트는 정적 모형을 측정하도록 교체했고 결과를 FIRST_PERSON_MEASUREMENTS.json에 따로 저장합니다. 후보 탐색 변경 전 최초 선택 424.6ms, 변경 후 103.5ms로 약75.6% 감소했습니다. 단일 장면·각1회 측정이며 전 지역이나 모든 기기의 개선율은 아닙니다. 이후 10회 표본에서 이동 그리기0.7–4.9ms, 눈높이1.699963m, 지도/Three 프레임 증가0, 페이지 예외0을 확인했습니다. ## 카메라 조작 회귀 — 변경 후 실제 버튼·휠·드래그·API 회귀 통과

수정 전 실제 브라우저에서는 눈높이 줌 약22.689에서 지도 자체의 **+** 버튼을 누르면 줌이 약20.080으로 내려가고 지형 배율도4배로 복원되는 현상을 확인했습니다. 카메라 API로 줌23.689를 지정한 뒤 지도가 정착하면 이전22.689로 되돌아가는 사례도 있었습니다.

현재 구현은 자체 눈높이 이동으로 표시되지 않은 `movestart`를 모두 감지해 길 고정을 해제하고, 조작 중 카메라·지형 배율을 유지하도록 바꿨습니다. 늦은 지형 보정도 수직 높이에만 적용합니다. 해당 버튼·휠·드래그·API 회귀는 이번 사람 1인칭·정적 모형 전환 후 전체 Chrome 26개 검사에서도 통과했습니다. 결과는 [VERIFICATION.md](../VERIFICATION.md)에 기록합니다.

세 표본의 감소율은 42.89–45.47%이며, 원본 geometry 참조와 상세 속성을 유지하는지 함께 검사합니다.

`mobility-verification.json`과 `production-mobility-verification.json`은 제거된 자동 이동의 과거 브라우저 표본입니다. 현재 정적 모형 검사는 `tests/mobility.spec.ts`를 통해 별도 `scale-references-verification.json`을 생성하도록 준비했습니다. 정착 뒤 프레임·좌표 불변, 최대 확대의 일반 지도에서 경로 요청 없음, 수동 이동·토글과 물리 치수를 확인합니다. 이번 실행은 아직 완료 수치로 기록하지 않았으며 [VERIFICATION.md](../VERIFICATION.md)에서 상태를 구분합니다.

브라우저 검사: DPR2에서 기본1.25/수동1·2 적용, 동네 카드·바로가기 제거, 실제 남산 숲240개 나무 렌더, 나무 토글·건물 토글 독립성과 같은 제외 영역 재요청 없음, 4종 모델 각1회 GLB 요청, 로딩 이후 idle 재렌더링 없음. 일반 지도·검색·모바일 회귀도 함께 검사합니다.

이는 로컬 Chrome의 기능·전송·불필요 작업 검증입니다. 모든 기기의 일정 FPS나 장시간 메모리 사용 감소율을 측정한 결과는 아닙니다. 빠르게 넓은 범위를 이동하면 원본 건물·등고선 geometry를 새로 처리하는 비용이 남으며, 확대 범위와 화면 선명도에 따라 부하가 달라집니다.

정적 모형 전환 전 확대 회귀에서 실제 +버튼은 22.689→23.689였고, 이어진 축소 4회도 1씩 감소하며 지형 1배를 유지했습니다. 모드 전환·재시도 실패 복구도 검사했습니다. [전후 기록](ZOOM_REGRESSION.json).
