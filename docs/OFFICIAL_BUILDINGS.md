# 공식 서울 건물 자료 연결 준비

확인일: **2026-09-08**. 공식 건물 외곽선과 건축물대장 높이를 함께 가진 자료의 제공 경로와 최신 컬럼 정의서를 확인했다. **서울 SHP 원본은 아직 내려받거나 이 앱의 DB에 적재하지 않았다.** 현재 지도에 표시되는 다른 출처의 건물을 공식 건물 자료로 해석하면 안 된다.

## 내려받을 자료

[VWorld GIS건물통합정보](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=NA&dsId=18)에서 **서울특별시 · 전체데이터 · SHP**를 선택한다. 공식 설명은 건물 공간정보와 세움터 건축물대장 속성정보를 건물 단위로 결합한 자료이다. [공공데이터포털의 동일 자료](https://www.data.go.kr/data/15083092/fileData.do)도 이 VWorld 경로를 안내한다.

|---|---|
| 화면상의 자료명 | GIS건물통합정보 / 서울특별시 / 전체데이터 |
| 기준일 | 2026-08-09 |
| 갱신일 | 2026-08-24 |
| 화면 용량 | 129 MB |
| 자료 식별자 | `dsId=18`, `svcCde=NA`, `dsFileId=20171128DS00010`, `fileNo=4455` |
| 전체 자료 테이블 코드 | `AL_D010` |
| 실제 ZIP 파일명·서울 건물 개수·높이 등록률 | 원본 미확보로 미확인 |

다운로드 버튼과 선택 다운로드 모두 비로그인 상태에서는 “로그인 후 이용해주세요.”를 표시하고 중단한다. 이 컴퓨터의 Chrome에서도 로그아웃 상태를 확인했다. **API 키 없는 파일 제공 경로는 있지만, 현재 확인된 다운로드에는 VWorld 로그인이 필요하다.** 새 계정 생성이나 로그인 우회는 수행하지 않았다.

전체 자료는 월간, 변동 자료는 일간 갱신으로 안내되어 있다. 첫 적재에는 전체 자료를 사용한다. 변동 자료를 전체 자료처럼 읽으면 누락과 열 해석 오류가 생긴다.

## 최신 정의서에서 확인한 필드

공식 페이지의 [국가중점데이터 컬럼 정의서 2026-01-02](https://www.vworld.kr/contents/국가중점데이터_컬럼정의서(26.01.02)_배포용.xlsx)를 실제 내려받아 XLSX 내부 표를 읽었다. `테이블정의서(전체)` 시트 **773–801행**, `AL_D010`, `A0`–`A28`이다. 아래 필드는 서울 SHP 자체를 검사한 결과가 아니라 최신 **정의서에서 확인한 구조**이다.

| 필드 | 정의 | 사용 시 주의 |
|---|---|---|
| A0 | 원천도형ID | 원천 식별자로 보존 |
| A1 | GIS건물통합식별번호 | 길이 28, 숫자처럼 보여도 문자열로 보존 |

| A8 / A9 | 건축물용도코드 / 건축물용도명 | 5자리 코드로 정규화하여 사용 |
| A12 | 건축물면적(㎡) | 대장 값; 도형에서 계산한 외곽선 면적과 별도 보존 |
| A13 | 사용승인일자 | 자료 기준일과 구분 |
| A14 / A15 | 연면적 / 대지면적(㎡) | 외곽선 면적과 혼동하지 않음 |
| **A16** | **높이(m)** | 양의 유효값만 등록 높이로 표시; 0·빈 값은 미등록 |

A8의 `02001`은 아파트, `02002`는 연립주택, `02003`은 다세대주택이다. `02000`은 더 넓은 공동주택 분류이다. 이름에 “아파트”가 있거나 층수가 높다는 이유만으로 아파트로 분류하지 않는다. 정의서의 숫자 예시에는 `2000`처럼 앞자리 0이 생략되어 있으므로 코드 해석 때 이를 복원해야 한다.

변동 자료의 `CH_D010`에는 추가 필드가 있다. 특히 **A23은 변동순번**, **A30이 원천시도시군구코드**이며 A29는 입력구분이다. 전체 자료의 A23과 의미가 다르다.

## 높이와 도형의 의미

표시할 A16은 **지자체에서 관리하고 국토교통부가 제공하는 건축물대장 기반의 등록 높이**이다. 모든 건물의 현재 지붕 높이를 현장에서 새로 측량한 값이라는 보증이 아니다. 누락·0값·원천 등록 오류·갱신 시차가 있을 수 있으며, 이번 조사에서는 개별 건물의 값이나 각 구별 등록률을 검증하지 않았다. 메타데이터의 `source_height_verified`는 `false`로 유지한다.

등록 높이를 지면의 해발고도로 해석하지 않는다. 지형 표면 위에 건물 높이를 더해 표시할 수 있지만, 그 표면도 이 앱에서는 보간한 지형이다. 외곽선을 일정 높이로 올린 건물은 배치와 크기를 표현하며, 지붕 형상·입면·외벽 색상·옥상 설비를 복원하지 않는다.

실제 ZIP을 확보하면 `.prj`를 읽어 좌표계를 판독해야 한다. [KTDB의 2024년 구축 보고서](https://www.ktdb.go.kr/DATA/pblcte/20250805093928585.pdf)는 과거 GIS건물통합정보를 EPSG:5174로 설명하지만, 이를 근거로 새 파일에 좌표계를 강제 지정하지 않는다. 높이의 현장 정확도와 세부 측정 기준은 별도 미확인 상태이다.

## 이용 조건에서 남은 불일치

VWorld 자료 상세 화면에는 **CC BY**, 원저작자를 밝히면 자유롭게 이용할 수 있다고 표시되어 있다. 공공데이터포털의 동일 `dsId=18` 자료는 **무료 · 이용허락범위 제한 없음**으로 안내한다. 다만 VWorld의 CCL 상세 링크는 `by-nc-nd/2.0/kr/`를 가리켜 **화면 문구와 링크가 서로 다르다**. 이 차이를 해소하지 않은 채 조건 없는 재배포가 확정됐다고 설명하지 않는다. 실제 파일에 동봉된 이용 조건도 확보 후 확인할 항목이다.

이름이 비슷한 [건물통합정보 마스터](https://www.data.go.kr/data/15146873/fileData.do)는 별도 자료(`dsId=30524`, `svcCde=MK`)이고 공공누리 **제4유형**으로 표시된다. 이 자료의 조건과 `dsId=18`의 조건을 섞어 해석하지 않는다. 이번 작업은 외부 업로드나 공개 배포를 포함하지 않는다.

## 서울시 대안 확인

**2026-09-08 추가 확인:** 아래의 파일 미확보 상태 이후 공개 Sheet의 CSV 다운로드 버튼을 추적해 OA-22424 원본 CSV 다운로드에 성공했습니다. 비로그인 공개 폼을 그대로 사용했으며 API의 sample 제한을 우회하지 않았습니다. 585,194행은 공식 sample API가 알리는 전체 개수와 일치합니다. 이 CSV에는 좌표·도형이 없고 기존 Overture에 공통 대장 식별자가 없으므로 운영 지도 높이는 아직 교체하지 않았습니다. 자세한 전수 결과와 품질 문제는 [REGISTER_CSV_AUDIT.md](REGISTER_CSV_AUDIT.md)를 참고하세요. 아래 문단은 이 추가 확인 이전 조사 경과입니다.

[서울시 건축물대장 표제부 OA-22424](https://data.seoul.go.kr/dataList/OA-22424/S/1/datasetView.do)는 실제 Chrome 화면에서 **2026-09-08 갱신 · 공공누리 제1유형**으로 표시된다. 최초 정적 페이지의 첨부 목록은 비어 있었으나, 후속 조사에서 동적으로 표시되는 Sheet 탭의 **내려받기(CSV)** 버튼을 확인했다. 로그인하지 않은 화면의 공개 폼으로 요청한 결과 **HTTP 200**, 첨부 파일명 **`서울시 건축물대장 표제부.csv`**, **CP949** CSV와 실제 건물 행을 받았다.

공개 버튼은 `https://datafile.seoul.go.kr/bigfile/iot/sheet/csv/download.do`에 POST한다. 페이지에 주어진 폼 값은 `srvType=S`, `infId=OA-22424`, `serviceKind=0`, `pageNo=1`, `ssUserId=SAMPLE_VIEW`, 나머지 검색조건은 비어 있는 기본값이다. `SAMPLE_VIEW`는 비로그인 방문자에게 페이지가 직접 제공하는 값이며, 로그인이나 키 제한을 우회하기 위해 변경한 값이 아니다. `filterCol`은 화면 기본값인 `필터선택`이다.

CSV에는 높이(`HG`에 해당하는 한글 열 `높이`), 지상·지하층수, 건축물대장일련번호, 동명, 지번·도로명 주소 등 **62개 열**이 있다. 후속 [전수 감사](REGISTER_CSV_AUDIT.md)에서 **585,194행**과 공개 API 전체 건수의 일치를 확인했다. 양수 높이는 **329,438행(56.2955%)**이며, 0·빈 값·음수뿐 아니라 양수 중 극단값도 있다. **원본 도형과 경위도 열은 없다.** 이 파일만으로 건물을 지도 위에 정확히 배치할 수 없으며, 다른 외곽선과 결합하려면 대장 식별자·주소·동별 대응을 검증해야 한다. 현재 CSV를 지도에 임의 매칭하거나 적재하지 않았다.

Sheet 화면은 최대 1,000건을 노출하고 전체 자료는 CSV로 확인하라고 안내한다. Open API `vBigDjrTitle`은 인증키가 필수이며, 공개 `sample` 키는 시작·종료 위치 1–5 범위, 최대 5건만 허용한다고 명시되어 있다. 정식 API 요청의 한 번당 상한은 1,000건이다. CSV 다운로드와 API 샘플 범위를 혼동하지 않는다.

[서울 데이터 허브의 국토교통부 표제부 자료](https://data.seoul.go.kr/bsp/wgs/dataView/data300View/630.do)도 높이·건물명·동명·층수 등을 설명한다. 여기서도 독립적인 건물 외곽선 전체 파일을 확인하지 못했다. **무키 공개 높이 CSV는 확보 경로가 검증됐지만, 로그인 없는 공식 서울 외곽선+높이 결합 SHP는 아직 확보하지 못했다.**

## 로컬 파일을 확보한 뒤 가져오기

`scripts/import_official_buildings.py`는 로컬 ZIP만 읽으며 다운로드나 로그인을 수행하지 않는다. 현재 `server/buildings.py`와 호환되는 건물 DB를 생성한다. 공식 전체 ZIP의 실제 파일명을 `--source`에 지정하고, **선택한 다운로드 행의 기준일**을 `--source-date`에 지정한다. 아래 날짜는 위에서 확인한 2026-08-09 전체 자료를 받을 때의 예시이다.

```sh
# 먼저 실행 중인 npm run dev/API를 종료한다.
.venv/bin/python scripts/import_official_buildings.py \
  --source /실제로/내려받은/서울-전체자료.zip \
  --source-date 2026-08-09
npm run dev
```

기본 대상은 `data/buildings.sqlite`이다. `--database`로 별도 DB에 먼저 시험할 수 있다. ZIP 안에 SHP가 여러 개라면 `--layer`에 ZIP 내부 경로에서 `.shp`를 뺀 이름을 정확히 지정한다. `.prj`, `.shp`, `.shx`, `.dbf`가 모두 필요하며, DBF는 `.cpg`를 따르고 없으면 `cp949`를 사용한다. 필요한 경우 `--encoding`을 명시한다.

가져오기 도구는 다음을 수행한다.

1. AL_D010의 A0–A28 구조와 서울 법정동 코드, 원본 도형의 유효성을 검사한다. 변동 자료·좌표계 누락·서울과 맞지 않는 좌표는 오류로 중단한다. 도형을 임의로 고치거나 제외하지 않는다.
2. 원본의 구멍과 분리된 다각형을 유지한 채 `.prj`에 따라 WGS84로 변환한다. 면적은 EPSG:5186에서 계산하며 A12 대장 면적은 별도로 보존한다.
3. A16의 양수만 `height_status=reported`, `height_source=국토부 건축물대장`으로 제공한다. 0·음수·빈 값은 `height_m=null`이며 층수로 채우지 않는다. 숫자가 아닌 값이나 무한대는 오류로 중단한다.
4. 원본 모든 속성을 무손실 zlib JSON으로 저장한다. 원본 ZIP도 SHA-256 이름으로 `data/sources/official-seoul-<sha256>.zip`에 보관한다.
5. 새 DB를 임시 파일에 완성하고 무결성을 확인한다. 이전 DB를 `data/buildings.previous-<UTC시각>.sqlite`에 백업한 다음 원자적으로 교체한다. 기존 원본 ZIP과 이전 DB는 자동 삭제하지 않는다.

같은 ZIP·기준일·설정으로 다시 실행하면 기존 DB를 재사용한다. 데이터나 가져오기 설정이 달라지면 새로 만든다. 실행 중 대상 DB가 바뀌면 다른 작업의 결과를 덮어쓰지 않고 중단한다. 교체 후 API를 재시작하고 `/api/buildings/meta`의 `source_kind=official_gis_buildings`, 실제 개수와 높이 등록률을 확인한다.
