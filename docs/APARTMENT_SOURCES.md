# 아파트 관련 공개 자료 목록

확인일: **2026-09-10**. 이 문서는 아파트 단지·동·건물 정보를 지도와 연결하기 위해 조사하고 받아 둔 **공개 자료의 목록**이다. 여기서 "수집"은 원본 파일을 `data/sources/<slug>-2026-09-10/`에 그대로 보존하고 요청 방식·바이트 수·SHA-256·포털 건수·이용조건을 `manifest.json`에 기록했다는 뜻이다. 자료를 해석하거나 지도에 표시했다는 뜻이 아니다. 같은 단지코드의 K-apt 위치 보완을 지도에 반영한 것은 [400세대 이상 단지 문서](APARTMENTS_400.md)에 별도로 기록했고, 로컬 DB 적재 결과는 [적재 결과](APARTMENT_SOURCES_IMPORT.md)에 있다. 이 문서의 숫자는 모두 manifest와 조사 기록(`candidates.json`)을 스크립트로 읽어 적었다.

- 서울 Sheet 12건은 모두 별도 건수 응답과 CSV 행 수가 일치했다(`count_matches_csv=true` 12건, 불일치 0건). 다만 하루 전 조사 기록의 건수와는 4건이 달랐다. OA-22423 19,233→19,231, OA-22414 59,307→59,321, OA-20281 6,600→6,603, OA-15822 79,000→80,594. 이 자료들은 매일 갱신되므로 **포털 건수는 받은 날의 값**이며 코드에 고정할 수 없다.
- 서울도시공간포털 ArcGIS 두 레이어는 objectId 수와 받은 도형 수가 같다(UQ120 2,989, UQ181 3,329). 원본 좌표계는 `wkid 102086 / latestWkid 5174`이고 응답은 `outSR=4326`으로 요청한 결과다. 레이어 메타데이터의 `copyrightText`는 비어 있다.
- 공공데이터포털의 "전체 행" 표기와 파일 행 수를 비교할 수 있었던 항목 중 한국부동산원 두 자료가 크게 다르다. 기본정보 `15106861`은 포털 44,628 대 파일 **307,407**, 동정보 `15106866`은 포털 160,020 대 파일 **464,807**이다. 파일 행 수를 기준으로 삼고 두 값을 모두 기록했다. 단지명 이력 8,905, LH 6,217·24,259, HUG 1,432, 신규 단지 678, 자치구 현황 75·331·203·270·141·258·126은 포털 표기와 파일이 같았다. 공시가격 zip `3073746`의 포털 표기 15,580,435행은 zip을 열지 않아 비교하지 못했다.
- CSV 35개는 `utf-8-sig` 또는 `cp949`로 엄격 디코딩에 성공했고(cp949 27, utf-8-sig 8), 35개 모두 모든 행의 열 수가 머리글과 같았다. 서울 Sheet·서울 첨부·LH·신규 단지·다수 자치구 파일은 cp949, 한국부동산원·HUG·중랑구·성동구 파일은 utf-8-sig다.
- 186개 파일 전부에 SHA-256을 기록했고, 이 문서를 쓰면서 디스크의 파일 크기가 manifest의 bytes와 모두 같음을 다시 확인했다.
- 주택인허가 동별개요 OA-22414의 42열에는 `높이`, `지상층수`, `지하층수`, 임대·분양 유형별 세대수 열이 있다. 총괄표제부 OA-22423의 53열에는 `세대수`, `주건축물수`, `총주차수`, `사용승인일자`가 있다. 열 이름을 확인한 것이며 값의 정확성을 확인한 것은 아니다.
- K-apt 주간 xlsx는 자료실 공지(seq 134942)의 첨부이며 공지의 추출일은 2026-09-09다. 한국부동산원 파일명의 `20250918`은 자료 기준일로 보이고 포털 수정일은 2026-03-06(기본정보)·2025-11-11(동·이력)이다. 두 날짜를 같은 것으로 취급하지 않는다.

manifest에서 발견한 불일치와 빈틈:

- 공공데이터포털 23건의 `portal_license_text`는 모두 `null`이다. 페이지의 이용허락범위 문구를 정규식으로 뽑지 못했고, 표의 이용조건은 등록부 상수다. 조사 기록에는 각 페이지가 "이용허락범위 제한 없음"을 표시한 증거가 있다.
- 도로명주소 건물DB 응답의 `Content-Type`은 `application/json`이지만 실제 본문은 35개 파일이 든 zip이다(`is_zip=true`). 건축HUB 두 응답은 `content_type`이 `null`이다. ArcGIS 두 manifest에는 `http_status`·`content_type` 키가 없고, SH 목록 manifest의 `http_status: 200`은 코드가 고정으로 적은 값이다.
- 정보몽땅 xls의 `Content-Disposition` 파일명은 깨진 문자열(`ì¬ìì¥ëª©ë¡.xls`)이었고 스크립트가 latin-1→UTF-8로 복원해 `사업장목록.xls`로 저장했다.
- 금천구 `15102426`은 포털 제목이 "공동주택(아파트) 용도 및 면적 현황"인데 받은 파일명은 `공공데이터포털 데이터(아파트 단지내 조경면적).csv`다. 14열에 대지·건축·연면적, 조경면적, 주용도, 세대수 열이 함께 있어 제목과 내용이 어긋난 것은 아니지만 파일명은 다르다. 서대문구 파일명에는 `(1)`이 붙어 있어 제공기관이 재업로드한 복사본으로 보인다.
- 강서구와 양천구는 각각 서울열린데이터광장 첨부(OA-21838 xlsx 2025-08-01, OA-22047 csv 2023-03-07)와 공공데이터포털 파일(15066129 2023-09-05, 15052389 2026-03-11)이 따로 있어 둘 다 받았다. 양천구 두 파일은 270행으로 같지만 열 수가 14와 15로 다르다. 어느 쪽이 최신 원본인지 정하지 않았다.
- OA-12027·OA-22856의 이용조건 문구에 붙은 "(공공데이터포털 표기)"는 위에서 적었듯 서울열린데이터광장 페이지 표기다.

검증하지 않은 것:

- **어떤 자료의 값도 현장이나 다른 출처와 대조하지 않았다.** 행 수·열 수·해시·인코딩만 확인했다.
- zip 안의 CSV는 열지 않았다. 공시가격 zip의 CSV는 압축 해제 시 3,457,575,809 bytes, 전월세가 2025 CSV는 155,574,646 bytes, 건물에너지 txt는 170,681,500·47,407,133 bytes, 도로명주소 건물DB는 35개 파일이다. xlsx·xls도 열지 않았다. SH 목록 HTML 91쪽은 표를 파싱하지 않았고, 페이지의 목록 번호가 909에서 1까지라는 것만 manifest에 남았다.
- K-apt, 서울도시공간포털, 정보몽땅, SH, 도로명주소 개발자센터, 건축HUB 자료의 재배포 조건은 확인하지 못했다. 서울시 저작권 정책은 공공누리 표시가 없는 자료를 담당자와 협의하도록 안내한다([공개 도형 조사](PUBLIC_MAP_SOURCES.md) 참고).
- K-apt 좌표의 투영 정의는 사이트 스크립트 `knew_map.js`의 TM 중부 정의를 그대로 적은 것이고, 서대문구 파일의 X/Y 좌표계는 페이지에 표기가 없다. ArcGIS 응답의 4326 변환 정확도도 검사하지 않았다.
- 한국부동산원 단지고유번호, K-apt 단지코드, 도로명주소 건물관리번호, 건축물대장 일련번호가 서로 어떻게 대응하는지는 [아파트 데이터 연결 설계](APARTMENT_DATA.md)의 원칙대로 코드 일치 이외의 방법으로 확정하지 않았다.

## 재수집

```sh
.venv/bin/python scripts/fetch_apartment_sources.py            # 등록부 48개 전체
.venv/bin/python scripts/fetch_apartment_sources.py --list     # 등록부 확인
.venv/bin/python scripts/fetch_apartment_sources.py --only kapt-seoul-complex-poi,seoul-register-summary-oa-22423
.venv/bin/python scripts/fetch_apartment_sources.py --only seoul-register-summary-oa-22423 --force
```

- 출력 폴더는 `data/sources/<slug>-<실행일>/`이다. 실행일이 폴더 이름에 들어가므로 다른 날 실행하면 새 폴더가 생기고 이전 폴더는 그대로 남는다. 어느 날짜의 자료를 적재할지는 가져오기 쪽에서 정한다.
- 같은 날 다시 실행하면 `manifest.json`이 있는 폴더는 건너뛴다(`skipped (manifest exists)`). 같은 날짜 폴더를 새로 받으려면 `--force`를 쓴다. `--skip`으로 일부를 빼고, `--workers`(기본 5)로 동시 요청 수를 정한다.
- 실패한 자료는 해당 폴더에 `error.json`(오류와 traceback)만 남고 manifest는 만들지 않으며, 하나라도 실패하면 종료 코드 1이다. 성공하면 `error.json`을 지운다.
- 서울 Sheet의 건수는 매일 바뀌므로 **예상 건수를 코드에 두지 않는다.** 실행 시점의 별도 건수 응답을 `independent_count`와 `sheet-count-response.txt`로 manifest에 남기고 CSV 행 수와 비교한 결과를 `count_matches_csv`에 적는다. 가져오기에서 건수를 검사하려면 이 manifest 값을 읽는다.
- K-apt는 방문 페이지의 `_csrf` 토큰과 세션 쿠키를 그대로 사용하고, 건축HUB는 목록 페이지의 토큰과 함께 `srvrFileNm`을 보낸다. 건축HUB 파일 id(`OPN...`)는 매월 바뀌며 현재 목록에 없으면 스크립트가 오류로 멈춘다. 이때 등록부의 `srvrFileNm`과 `label_hint`를 새 월분으로 바꿔야 한다. 전월세가 zip의 `seq`, 강서구 xlsx·양천구 csv의 `seq/infSeq`도 포털이 첨부를 바꾸면 갱신해야 한다.
- 스크립트는 파일을 변형하거나 병합하지 않는다. 적재·선별·조인은 [적재 결과](APARTMENT_SOURCES_IMPORT.md)에 적은 별도 가져오기 도구가 한다.
