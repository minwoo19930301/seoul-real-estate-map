# 서울 400세대 이상 공식 공동주택 연결

2026-09-09 서울열린데이터광장 **OA-15818 서울시 공동주택 아파트 정보**의 공개 CSV 전체를 받았다. 원본 2,887개 단지 코드 중 아파트·주상복합으로 등록됐고 `TNOHSH >= 400`인 **1,363개**를 확인했다. 좌표 검사, 같은 단지코드의 K-apt 위치 보완, 제한된 OSM 보완 후 **1,359개**를 지도·검색에 연결했다(2026-09-10 갱신, 이전 1,344개). 나머지 4개는 다른 단지와 좌표를 공유해 위치가 불확실하므로 표식을 만들지 않았다. 원본 전체와 제외 이유는 보존했다.

이 숫자는 해당 공개 자료에 등록된 **단지 코드별 전체세대수**를 기준으로 한다. 현실의 서울 모든 단지를 빠짐없이 포괄했다는 뜻이 아니다. 분양과 임대가 별도 관리단지 코드로 등록될 수 있으며, 두 코드를 임의로 합산하거나 아파트 동별 건축물대장 세대수를 단지 총세대수로 대체하지 않는다.

## 원본 취득과 전수 확인

- [서울시 공식 데이터셋](https://data.seoul.go.kr/dataList/OA-15818/S/1/datasetView.do): 원본 시스템 서울특별시 공동주택통합정보마당, 공개 페이지 갱신일 2026-09-08, 공공누리 제1유형(출처표시, 상업적 이용·변경 가능).
- [실제 Sheet 공개 폼](https://data.seoul.go.kr/dataList/sheetView.do?infId=OA-15818&srvType=S): `TNOHSH`=k-전체세대수, `APT_CD`=k-아파트코드, `APT_NM`=k-아파트명, `CMPX_CLSF`=단지분류, `XCRD/YCRD`=좌표X/Y. 현재 CSV는 47개 열이며 폐지된 법정동주소 열은 요구하지 않는다.
- 공개 페이지는 화면 표가 최대 1,000건이며 전체는 CSV로 받으라고 안내한다. 실제 CSV **2,887행 × 47열**과 별도 공개 Sheet 응답 `totalCount:2887`을 비교했다. 1,000행 샘플을 전체로 취급하지 않았다.
- 원본 CSV **1,428,766 bytes**, SHA-256 `68fa3d0a536ba4cd573ae2516eb3b2d202c1c176ece97a324e13bc664ecae3a3`. CP949 엄격 디코딩과 CSV 파싱에 성공했다. 코드 2,887개 모두 고유하고 비어 있지 않으며 `USE_YN=Y`다.
- 원본 폴더: `data/sources/seoul-apartments-2026-09-09/`. CSV와 Sheet HTML, 별도 건수 응답, 취득 경로·해시 manifest를 함께 보존한다. 공개 화면이 제공한 익명 CSV 폼을 사용했다. API 키·로그인·BrightData를 사용하지 않았다.

## 위치 검증과 보완

공식 좌표를 무조건 정확하다고 가정하지 않았다. 좌표의 유한성, 서울 경계, 원본 구 이름과의 공간 일치를 검사했다. 같은 숫자 좌표를 가진 그룹은 41개였다. 문자열의 소수점 자릿수만 다른 경우도 숫자로 비교했다. 서로 다른 도로명주소가 같은 좌표를 쓰는 경우 검토 대상으로 분리했다. 같은 주소를 공유하는 분양·임대 등록은 원본 좌표 공유 상태를 표시한다.

400 이상 연결 기록의 위치 출처는 공식 등록 좌표 **1,295개**, 동일 주소의 공식 공유 좌표 **29개**, K-apt 단지코드 일치 보완 **29개**, OSM 보완 **6개**다. 전체 원본에서는 K-apt로 78개, OSM으로 7개 위치를 보완했다. 우선순위는 검증된 공식 좌표 → K-apt 단지코드 일치 → OSM 이름·구 일치 → 미해결이다.

OSM 보완은 보관한 원본에서 `landuse=residential`인 영역 중 **같은 구 + 정규화한 전체 이름이 유일하게 일치**하는 경우만 허용한다. 정규화는 공백·문장부호·대소문자와 일반적인 말미 `아파트` 표기만 처리한다. 단지 차수, 숫자, 임대/분양, 동 이름을 삭제하지 않는다. 모호한 후보 2개 이상은 선택하지 않는다. 유사도·가까운 거리만으로 이름을 붙이거나 좌표를 생성하지 않는다.

공식 좌표가 잘못되었거나 누락됐을 때만 위 일치의 OSM 위치를 사용한다. 공식 위치와 유일한 OSM 후보가 750m 넘게 어긋나도 검토 대상으로 처리한다. 보완 좌표는 원본 OSM node 또는 `out center`의 영역 bounding box 중점이다. 영역 내부·출입구·측량점 보장이 아니다. 원래 공식 X/Y, 보완한 X/Y, 이유, OSM 객체 ID와 URL을 **별도 필드로** 유지한다. OSM 자료의 기준 시각은 `2026-06-01T08:52:28Z`다.

실제 회귀 사례:

- `잠실엘스아파트`(A13822004, 5,678세대)와 `잠실리센츠`(A13822003, 5,563세대)는 공식 원본에서 같은 좌표 `127.088451,37.5127515`로 등록되어 있었다. 서로 다른 도로명주소와 정확한 단지명 OSM 일치를 확인해 각각 [잠실 엘스](https://www.openstreetmap.org/relation/6114967) `127.0814378,37.5141602`, [잠실 리센츠](https://www.openstreetmap.org/relation/6114968) `127.088489,37.5143342`로 표시했다. 세대수는 OSM에서 가져오지 않았다.
- 공식 좌표가 비어 있던 문래롯데캐슬아파트 499세대, 개봉역 센트레빌레우스 1,089세대, 강동리버스트6단지 1,244세대, 강동리엔파크13단지아파트 675세대는 같은 이름·구의 원본 영역으로 연결했다.
- `월계주공1단지`는 같은 이름의 OSM 영역이 2개여서 임의로 고르지 않았고, K-apt 좌표도 다른 단지와 공유된 점이어서 미해결로 남겼다. `고척아이파크MD/RD`를 이름이 일부 겹치는 한 개의 고척아이파크 영역에 임의 배분하지 않았다.

## K-apt 단지코드 일치 위치 보완 (2026-09-10)

[공동주택관리정보시스템 K-apt 단지 위치 페이지](https://www.k-apt.go.kr/kaptinfo/openKaptLocation.do)가 공개 지도에 쓰는 POI 응답을 로그인·API 키 없이 받았다(`data/sources/kapt-seoul-complex-poi-2026-09-10/`, `bjdCode=11`, 3,771행·단지코드 3,432개). 이 `kaptCode`는 서울시 OA-15818의 `k-아파트코드`와 같은 체계이므로 이름이 아니라 **코드 일치**로만 연결했다. 좌표는 K-apt 지도 스크립트가 쓰는 TM 중부 정의를 그대로 사용했고, 그 정의는 EPSG:5174와 같다. 공식 좌표가 정상인 2,703개 단지와 비교하면 중앙값 차이 16.8m, 90퍼센타일 121m였다.

K-apt 좌표도 무조건 믿지 않았다.

- 한 단지코드에 POI가 여러 개면 모든 점이 서로 100m 안에 있을 때만 그 점들의 평균을 쓰고(`kapt_poi_cluster_mean`), 더 벌어지면 모호한 것으로 처리해 쓰지 않았다(117개 코드).
- 서로 다른 단지코드가 같은 좌표를 쓰면 어느 단지의 위치도 아니라고 보고 쓰지 않았다(91개 코드). 0,0처럼 서울 밖에 찍힌 좌표 2개도 제외했다.
- 남은 좌표도 원본 구 경계 안에 있어야 한다. 검증된 공식 좌표가 있는 단지는 K-apt로 바꾸지 않는다.

그 결과 공식 좌표가 없거나 잘못된 단지 78개(400세대 이상 29개)를 K-apt 위치로 연결했다. 종전 OSM 보완 33개 중 26개는 코드 일치가 우선해 K-apt 위치로 바뀌었고 7개는 K-apt에 쓸 수 있는 좌표가 없어 OSM 위치를 유지했다. 400세대 이상 미해결은 19개에서 4개(대청, SH공사대치1단지, 사당우성(4-3)아파트, 월계주공1단지)로 줄었다. 넷 모두 서울시 좌표와 K-apt 좌표가 각각 다른 단지와 공유된 점이어서 임의로 고르지 않았다.

불일치도 숨기지 않고 기록했다. 공식 좌표와 K-apt 좌표가 둘 다 유효한데 750m 넘게 어긋나는 단지가 24개 있으며 이 경우 공식 좌표를 유지하고 `official_kapt_location_disagreement_over_750m`로 표시했다. K-apt와 OSM 이름 일치 위치가 750m 넘게 어긋나는 단지는 11개이고, 그중 공식 좌표가 없어 K-apt가 선택된 5개(목동성원, 신동아아파트, 구로우성, 길음동부센트레빌, 대림동현대)는 `kapt_osm_location_disagreement_over_750m`로 표시해 검토 대상으로 남겼다. 전체 목록은 `/api/places/meta`의 `official_apartments`에 있다. K-apt 원본에는 `테슽002`처럼 시험용으로 보이는 행도 있으나 공식 단지코드와 일치하지 않아 연결되지 않았다. K-apt 페이지에는 이용조건 표기가 없어 재배포 조건은 확인하지 못했다.

## 구현과 인터페이스

`scripts/import_apartments.py`는 원본 모든 열을 압축 JSON으로 보존하는 `data/apartments.sqlite`를 만든다. 공식 코드를 TEXT 기본키로 쓰고 `household_count`, `classification`, `target_400`, 공식/해결 좌표, 연결 근거를 별도 저장한다. 중복 코드·잘린 CSV·잘못된 정수·예상 전체 건수 불일치 시 기존 DB를 보존하고 실패한다.

`scripts/build_places.py`는 공식 DB의 위치가 있는 2,867개 기록을 기존 Places 인덱스에 추가한다. 같은 이름·구로 연결된 OSM 표식은 원본 ID를 보존하며 공식 기록에 합친다. 현재 총 검색 기록은 **43,809개**다(2026-09-10, K-apt 보완으로 52개 증가). 건물 이름·동 이름으로 세대수를 만들지 않는다.

검색/Point 속성에 `household_count`, `official_complex_code`, `apartment_class`, `household_count_source`, `household_count_status`, `source_updated_at`, `coordinate_status`, `coordinate_source_url`을 추가했다. `subtitle`에도 단지 전체세대수와 위치 출처를 표시한다.

- `PlacesAPI.features(..., min_households=400)`은 **residential만** 공식 세대수·아파트/주상복합 분류로 제한한다. 역·다리·교차로는 이 조건의 영향을 받지 않는다. 기존 화면별 300개 상한과 `truncated` 표시는 유지한다.
- 일반 `PlacesAPI.search(q, limit)`는 400 제한을 적용하지 않는다. 선택적으로 `min_households`를 전달할 수 있다.
- `/api/places/meta`의 `official_apartments`에 전체 감사 결과와 미연결 19개 명단이 있다. 최상위 `official_complex_count_ge400=1363`, `mapped_complex_count_ge400=1344`도 제공한다.

## 재생성

```sh
.venv/bin/python scripts/import_apartments.py data/sources/seoul-apartments-2026-09-09/apartments.csv --source-date 2026-09-08 --expected-count 2887 --osm data/sources/osm-roads-2026-09-08/overpass.json --kapt-poi data/sources/kapt-seoul-complex-poi-2026-09-10/kapt-poi-seoul.json
.venv/bin/python scripts/build_places.py --overpass data/sources/osm-roads-2026-09-08/overpass.json --overpass-endpoint https://overpass.kumi.systems/api/interpreter
.venv/bin/python -m unittest tests.test_places tests.test_apartments -v
```

두 빌더는 로컬 캐시만 읽고 임시 SQLite의 무결성을 확인한 뒤 원자적으로 교체한다. 네트워크를 다시 호출하지 않는다. 미래 원본으로 갱신할 때 `--expected-count`와 `--source-date`는 그때 실제 받은 공식 응답·페이지를 기준으로 바꾼다.

검증: 기존 장소 테스트 9개, 아파트 테스트 5개, K-apt 보완 테스트 6개 통과(2026-09-10). 399/400 경계, 원본 0/빈값, 연립주택 제외, 원본 열의 무손실 보존, 단지 코드 중복, 전체 건수 불일치, 좌표 오입력/누락·모호한 이름, 역을 보존하는 400 필터를 검사했다. K-apt 보완 테스트는 코드 일치 우선, 100m 군집 평균, 벌어진 점의 배제, 공유 좌표 배제, 서울 밖 좌표 배제, 유효한 공식 좌표 유지, 불일치 기록을 검사했다. 합성 fixture를 운영 데이터에 넣지 않았다.
